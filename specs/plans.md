# 工作计划与配套材料规范

`plans/` 保存待做工作的目标、实施安排、验收依据及未出版配套材料，入口为[工作计划与配套材料索引](../plans/README.md)。章节层级、内容提要及目标书稿结构统一放在 `outlines/`，遵循[大纲目录规范](outlines.md)。计划链接相应大纲，不复制一套章目作为执行清单。

## 计划的内容

每项相对独立的工作使用一份名称明确的 Markdown 文件，交代当前基线、要达到的结果、修改范围与实际状态。把工作按依赖关系拆成可执行的步骤，说明每步使用的材料、产生的结果，以及怎样判断完成。仅列“调整结构”“完善内容”等笼统动作不能表达实施安排。

涉及正文迁移时，应说明原材料与目标大纲的对应关系、尚缺内容、需要同步的正文大纲和出版入口，以及适用的构建和成品检查。结构决策仍在调整时如实标记，后续步骤可以据此安排，不把拟设章目写成已有正文。

计划中的日期、负责人和进度以实际约定及完成证据为准，不为了填字段设定期限。状态可使用“待开始”“进行中”“已完成”；部分完成时写明剩余工作。声称完成的步骤应能链接到相应文件、提交或检查结果。

## 未出版配套材料

与待办工作相关的未出版稿件、章内输入片段等材料在 `plans/` 中按任务建立子目录，保留来源及必要文件。子目录中的 `README.md` 说明材料来源、当前状态、预期归属和后续处理，并链接到相关工作计划及 `outlines/` 中的提要。当前保留的勒贝格稿件位于 `plans/volume-02-lebesgue-pending-migration/`。

材料尚未接入出版入口时须明确注明；保存原稿不代表相应正文已经完成。章节结构和内容提要仍统一放在 `outlines/`，例如 `outlines/pending-migration/`；材料迁入 `tex/` 后同步更新大纲、计划和入口，再按实际范围构建与检查。

## 索引与维护

`plans/README.md` 登记仍有效的工作计划、配套材料及其状态。执行中同步实际进展、范围变化和剩余问题；计划完成后简要记录结果与验证，历史细节由 Git 保存。只整理目录或编写计划，不据此实施计划中的正文重组。

正文发生变化时，仍须同步 `outlines/current/` 中对应提要，并遵循[开发要求](development.md)。计划不能替代正文、大纲或验证结果，也不保存聊天记录和一次性构建日志。
