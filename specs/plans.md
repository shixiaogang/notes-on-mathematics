# 工作计划规范

`plans/` 保存已确定、尚待执行的工作方案，入口为[工作计划索引](../plans/README.md)。计划同时保留目标内容和实施安排：书稿重组计划应完整说明各卷、部分和章节的职责、内容及相互分工，并据此安排材料迁移、正文修订与验收。

## 当前唯一计划

当前只有[十卷重组计划](../plans/ten-volume-migration/README.md)这一项待执行计划，全部文件集中在 `plans/ten-volume-migration/`。总入口保留已确定的十卷、30个部分、148章的分工与内容，链接30份逐部分细纲，并给出实施安排和完成依据。

十卷计划正在分批实施：卷一至卷四（14部分、75章）已迁入正文，卷五至卷十待实施；迁移前的五卷正文与旧提要保存在 `tex_bak/`，作为后续迁移的来源。当前正文提要保存在 `outlines/`，遵循[大纲目录规范](outlines.md)。十卷计划引用的旧五卷细化材料保存在其 source-outline/ 下，作为来源细纲，不另立待执行计划。正文基线、目标内容和实施进度分别说明，不用目标章数表示已有正文完成量。

## 计划的内容与维护

计划保留各卷、部分和章节处理的具体问题、材料归属及相互依赖，并提供相应细纲。涉及章节层级、`paragraph` 和自然段提要时，沿用[大纲写作要求](outlines.md#大纲的写作组织)。结构清单与计划总索引、逐部分文件同步，避免章目、标题或内容分工发生漂移。

实施安排说明当前基线、修改范围及依赖顺序，按可执行步骤交代使用的材料、产生的结果和验收依据。正文迁移须核对原材料与目标章纲的对应关系、尚缺内容、当前正文提要与出版入口，以及适用的构建和成品检查。

日期、负责人和进度以实际约定及完成证据为准。状态可使用“待执行”“进行中”“已完成”；部分完成时写明剩余工作，声称完成的步骤链接相应文件、提交或检查结果。只整理计划目录和内容归属，不据此实施计划中的正文重组。

## 索引与进度

`plans/README.md` 只登记当前这一项待执行计划。执行中同步进展、范围变化与剩余问题，计划完成后简要记录结果与验证，历史细节由 Git 保存。计划不能替代正文或验证结果，也不保存聊天记录和一次性构建日志。
